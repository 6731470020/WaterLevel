# ระบบวัดระดับน้ำอัตโนมัติ

ระบบตรวจวัดระดับน้ำจากภาพกล้องวงจรปิดด้วยปัญญาประดิษฐ์ สำหรับหน่วยงานท้องถิ่น
เขียนด้วย **Node.js เชิงวัตถุ (OOP)** — JavaScript ล้วน ไม่มีขั้นตอน build ไม่ใช้ Docker

> เอกสารข้อกำหนดและการออกแบบฉบับเต็มอยู่ที่ [`CLAUDE.md`](./CLAUDE.md)

---

## เริ่มใช้งานใน 2 คำสั่ง

```bash
npm install
npm start
```

เปิดเบราว์เซอร์ไปที่ **http://localhost:3000/setup** แล้วทำตามขั้นตอนบนหน้าจอ

ตัวช่วยติดตั้งจะให้เลือกชนิดฐานข้อมูล ทดสอบการเชื่อมต่อ สร้างตาราง
ใส่ข้อมูลตั้งต้น สร้างผู้ดูแลคนแรก แล้วเริ่มระบบใหม่ในโหมดใช้งานปกติให้อัตโนมัติ

> 🔒 หน้า `/setup` เปิดได้เฉพาะตอนที่ระบบยังไม่มีผู้ใช้แม้แต่คนเดียว
> เมื่อสร้างผู้ดูแลคนแรกแล้วจะถูกปิดถาวร

### เลือกฐานข้อมูลแบบไหนดี

| | **SQLite** (แนะนำสำหรับเริ่มต้น) | **MySQL 8 / MariaDB** |
|---|---|---|
| ติดตั้ง | ไม่ต้องทำอะไรเพิ่ม | ต้องติดตั้งเซิร์ฟเวอร์แยก |
| สำรองข้อมูล | คัดลอกไฟล์เดียว | ใช้ `mysqldump` |
| เขียนพร้อมกัน | ทีละคำสั่ง | รองรับพร้อมกันได้ดี |
| เหมาะกับ | จุดวัดไม่กี่แห่ง | ใช้งานจริงระยะยาว |

สลับได้ภายหลังโดยแก้ `DB_DRIVER` ใน `.env` แล้วรัน `npm run db:setup` ใหม่

## ติดตั้งด้วยบรรทัดคำสั่ง

เหมาะกับการติดตั้งอัตโนมัติหรือเซิร์ฟเวอร์ที่เข้าหน้าเว็บไม่ได้

```bash
npm install
cp .env.example .env
#   ตั้ง DB_DRIVER=sqlite (หรือ mysql พร้อมค่า DB_*) และ SESSION_SECRET
#   สุ่ม secret:  node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

npm run db:setup                 # สร้างตาราง + ข้อมูลตั้งต้น (สิทธิ์ 32 ข้อ · บทบาท 4 ตัว)
npm run create:admin             # สร้างผู้ดูแลคนแรกแบบโต้ตอบ
npm start
```

สร้างผู้ดูแลแบบไม่โต้ตอบ (สำหรับสคริปต์ติดตั้ง):

```bash
npm run create:admin -- --username admin --email admin@example.go.th \
                        --name "ผู้ดูแลระบบ" --password 'รหัสผ่านของคุณ'
```

> ⚠️ การส่งรหัสผ่านทางบรรทัดคำสั่งทำให้รหัสปรากฏใน process list และ shell history
> ควรใช้เฉพาะในสภาพแวดล้อมที่ควบคุมได้

## ตั้งค่าโซนเตือนภัยและจุดเทียบค่า

ขอบบนของโซนแต่ละโซนคือพิกเซล Y ที่ผู้ดูแล**รู้ระดับน้ำจริงอยู่แล้ว** เช่น "โซนวิกฤตมาก
เริ่มที่ 2.50 เมตร" ซึ่งเป็นข้อมูลชุดเดียวกับจุดเทียบค่าทุกประการ

ในเครื่องมือวาด ROI (`/admin/stations/:id/roi`) แต่ละโซนจึงมีช่อง **"ระดับน้ำ (ม.)"**
กรอกแล้ว**ระบบสร้างจุดเทียบค่าที่พิกเซลนั้นให้อัตโนมัติตอนบันทึก** ไม่ต้องไปกรอกเลข
ชุดเดิมซ้ำในหน้าเทียบค่าอีก — ซึ่งนอกจากเสียเวลาแล้วยังเสี่ยงกรอกไม่ตรงกันจนคำนวณเพี้ยน

| | จุดจากโซน | จุดที่กรอกเอง |
|---|---|---|
| แก้ที่ไหน | เครื่องมือวาด ROI | หน้า `/admin/stations/:id/calibration` |
| หน้าเทียบค่าแสดงเป็น | แถวอ่านอย่างเดียว ติดป้าย "จากโซน …" | แถวแก้ไขได้ |
| ย้ายโซน / ลบค่าเมตร | จุดย้ายตามหรือหายตามทันที | ไม่ถูกกระทบ |

- ใช้ปนกันได้ — โซนตั้งจุดหลัก แล้วเพิ่มจุดกรอกเองเสริมช่วงที่โซนไม่ครอบคลุม
- ถ้าพิกเซลชนกัน **โซนชนะ** และระบบจะเตือนว่าทับจุดไหนไป
- ต้องมีอย่างน้อย 2 จุด (นับรวมทั้งสองแบบ) ระบบจึงแปลงพิกเซลเป็นเมตรได้

> พิกเซลมาก = น้ำต่ำ (แกน Y นับจากบนลงล่าง) ระดับน้ำของโซนจึงต้องลดลงตามพิกเซล
> ที่เพิ่มขึ้น ถ้ากรอกกลับหัวระบบจะเตือนทั้งในเครื่องมือวาด ROI และตอนบันทึก

## ช่องทางแจ้งเตือน

รองรับ **LINE Messaging API · Discord · Telegram** เลือกพร้อมกันได้หลายช่องทาง

ตั้งค่าได้สองทาง — **หน้า `/admin/settings`** (สะดวกกว่า ไม่ต้อง SSH ไม่ต้องรีสตาร์ต)
หรือไฟล์ `.env` ค่าที่ตั้งผ่านหน้าเว็บ**ชนะ**ค่าใน `.env` เสมอ ส่วน `.env` เป็นค่าตั้งต้น
และเป็นทางถอยเมื่อยังไม่เคยตั้งผ่านเว็บ — ล้างค่าในหน้าเว็บแล้วจะกลับไปใช้ `.env` เอง

| ช่องทาง | ต้องมี | หาได้จาก |
|---|---|---|
| LINE | Channel Access Token · Channel Secret | LINE Developers Console |
| Discord | Webhook URL | ตั้งค่าช่อง → Integrations → Webhooks |
| Telegram | Bot Token · Chat ID | @BotFather · `api.telegram.org/bot<TOKEN>/getUpdates` |

- ช่องทางหนึ่งล้ม **ไม่ทำให้ช่องทางอื่นล้มตาม** และระบบบันทึกว่าใครไม่ได้รับลง `broadcast_logs`
- โทเคนที่เก็บในฐานข้อมูล**ไม่เคยถูกส่งกลับมาแสดงบนหน้าเว็บ** เห็นได้แค่ 4 ตัวท้าย
- `audit_logs` บันทึกแค่ว่าคีย์ไหนถูกแก้ ไม่บันทึกค่า
- เลือกช่องทางแล้วไม่กรอกค่าที่จำเป็น ระบบปฏิเสธตั้งแต่ตอนบันทึก ไม่ปล่อยให้ไปล้มตอนน้ำท่วม

> ⚠️ Channel Access Token ที่พบใน `data/` ถือว่ารั่วแล้ว ต้องออกใหม่ก่อนใช้งานจริง

## ย้ายข้อมูลจากระบบเดิม

อ่านจากไฟล์ `data/bangpai.sql` โดยตรง — **ไม่ต้องมี MySQL บนเครื่อง**

```bash
npm run migrate:legacy -- --dry-run --skip-images   # ดูผลก่อน
npm run migrate:legacy                              # ย้ายจริงพร้อมคัดลอกภาพ
```

สิ่งที่ตัวย้ายข้อมูลทำมากกว่าการคัดลอกตรง ๆ:

- **คำนวณ `water_level_m` ย้อนหลัง** จากจุดเทียบค่าของจุดวัดนั้น (ระบบเดิมไม่เก็บไว้)
- แปลงชื่อโซนภาษาไทยเป็นคีย์ภาษาอังกฤษ พร้อมรายงานแถวที่โซนเดิมไม่ตรงกับขอบเขตปัจจุบัน
- แตก `configs.config_data` JSON ออกเป็นตาราง `station_rois` (รองรับ config เวอร์ชัน 2.0 และ 3.0)
- ย้ายไฟล์ภาพเข้าโครงพาธใหม่ที่แยกตามวันที่ ทำเป็นชุดละ 100 ไฟล์และทำต่อจากจุดที่ค้างได้
- ตรวจสอบผลอัตโนมัติ: จำนวนแถว ช่วงค่าพิกเซล การคำนวณเมตร และจำนวนภาพ

รันซ้ำได้โดยไม่ทำข้อมูลซ้ำ ผู้ใช้เดิมย้ายมาพร้อมแฮช bcrypt
เข้าสู่ระบบด้วยรหัสผ่านเดิมได้ แล้วระบบจะอัปเกรดเป็น scrypt ให้อัตโนมัติ

## โครงสร้างระบบ

```
เบราว์เซอร์  —  EJS + vanilla JS (RoiEditor, WaterChart, CameraSource)
      │ HTTP + session cookie
┌─────▼──────────────────────────────────────────────────┐
│  Routes → Middlewares (4 ด่าน) → Controllers          │  ชั้นนำเสนอ
├────────────────────────────────────────────────────────┤
│  Services  (ตรรกะธุรกิจ · ไม่มี SQL · ไม่รู้จัก HTTP)    │  ชั้นธุรกิจ
├────────────────────────────────────────────────────────┤
│  Repositories  (ที่เดียวที่เขียน SQL)                    │  ชั้นข้อมูล
├────────────────────────────────────────────────────────┤
│  Database (นามธรรม) → MySqlDatabase | SqliteDatabase   │
└────────────────────────────────────────────────────────┘

         ขนานกัน (โปรเซสเดียวกัน)
  Scheduler (node-cron) → Jobs → Services ชุดเดียวกัน
```

**กฎเหล็ก:** ชั้นบนเรียกชั้นล่างได้เท่านั้น ห้ามข้าม ห้ามย้อน
Job และ Controller ใช้ Service ชุดเดียวกันเพื่อไม่ให้ตรรกะซ้ำสองที่

### จุดที่ควรดูก่อนถ้าอ่านโค้ดครั้งแรก

| ไฟล์ | ทำไมถึงน่าสนใจ |
|---|---|
| `src/services/WaterLevelCalculator.js` | ตรรกะแปลงพิกเซล↔เมตร — หัวใจของระบบ ไม่มีค่าสำรองฮาร์ดโค้ด |
| `src/models/values/PixelLevel.js` | Value Object ที่ทำให้สลับหน่วยโดยไม่ตั้งใจไม่ได้ |
| `src/core/ServiceContainer.js` | ที่เดียวที่รู้ว่าคลาสใดพึ่งคลาสใด — จุดที่สลับ driver ได้ |
| `src/middlewares/StationScopeMiddleware.js` | เหตุผลที่ด่านที่ 4 ตอบ 404 ไม่ใช่ 403 |
| `src/jobs/DetectJob.js` | ลำดับการตรวจวัดและโหมดยืนยันค่าผันผวน |

## การตั้งค่า (`.env`)

ค่าที่ควรรู้จัก — ดูรายการเต็มใน [`.env.example`](./.env.example)

| ค่า | ความหมาย |
|---|---|
| `DB_DRIVER` | `sqlite` (ค่าเริ่มต้น) หรือ `mysql` |
| `DB_FILE` | พาธไฟล์ฐานข้อมูล เมื่อใช้ SQLite |
| `DETECTION_DRIVER` | `mock` = ข้อมูลจำลอง · `http` = เรียกบริการ AI จริง |
| `NOTIFICATION_DRIVER` | `console` = พิมพ์ลง log · `line` = ส่งเข้า LINE จริง |
| `SESSION_SECRET` | ต้องยาวอย่างน้อย 32 ตัวอักษร (หน้าตั้งค่าสุ่มให้อัตโนมัติ) |
| `ALLOW_PRIVATE_CAMERA_URL` | เปิดเมื่อกล้องอยู่ในเครือข่ายภายใน (ปิดไว้เพื่อกัน SSRF) |

การตั้ง `DETECTION_DRIVER=mock` กับ `NOTIFICATION_DRIVER=console` ทำให้ทดลองระบบได้ครบทุกฟีเจอร์
โดยไม่ต้องมีบริการ AI หรือ LINE Channel — และ**ไม่มีความเสี่ยงที่จะส่งข้อความทดสอบเข้ากลุ่มจริง**

ใช้ `node:test` ที่มากับ Node ไม่ต้องติดตั้งไลบรารีเพิ่ม

## นำขึ้นเซิร์ฟเวอร์จริง

1. ตั้ง `NODE_ENV=production` และ `BASE_URL=https://…` ใน `.env`
2. ใช้ `pm2` หรือ `systemd` ให้โปรเซสรันค้าง
3. วาง Nginx เป็น reverse proxy ข้างหน้าเพื่อทำ HTTPS

> **สำคัญ:** ภาพที่แนบไปกับข้อความ LINE ต้องเป็น URL **HTTPS สาธารณะ**
> ระบบจะไม่แนบภาพเมื่อ `BASE_URL` ยังเป็น `http://`

**ห้ามนำโฟลเดอร์ `data/` ขึ้นเซิร์ฟเวอร์จริง** — เป็นเอกสารอ้างอิงระบบเดิมที่มีค่าลับรั่วอยู่

### ค่าลับที่ต้องออกใหม่ก่อนใช้งานจริง

ค่าเหล่านี้พบอยู่ในซอร์สโค้ดของระบบเดิมใน `data/` จึงถือว่า**รั่วแล้ว**:

- รหัสผ่านฐานข้อมูล
- LINE Channel Access Token และ Channel Secret
- `WATER_API_KEY` ของบริการตรวจจับ

## ใบอนุญาตใช้งานระบบ

ระบบมีกลไกใบอนุญาตที่กั้นทุกหน้าเมื่อหมดอายุ (ยกเว้นหน้าเข้าสู่ระบบและหน้าแจ้งเตือน)
`npm run db:setup` จะสร้างใบอนุญาตทดลอง 1 ปีให้อัตโนมัติ แก้ไขได้ที่ `/admin/license`

ระบบที่ยังไม่ได้ตั้งค่าใบอนุญาตถือว่าใช้งานได้ปกติ — เพื่อไม่ให้ระบบที่เพิ่งติดตั้ง
ถูกกั้นจนเข้าไปตั้งค่าไม่ได้
